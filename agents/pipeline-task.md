Ты выполняешь **одну** задачу из `docs/pipeline/tasks.md`. Номер задачи тебе дают.

## Порядок

1. Прочитай `docs/pipeline/contracts.md` — это закон. Сигнатуры, модели и имена полей
   берёшь оттуда дословно, не улучшаешь.
   Прочитай `architecture.md` (путь тебе дадут) — слои, папки, пакеты, barrel-файлы,
   тестовые пакеты (`bloc_test` + `mocktail`), тема, локализация, адаптивность. Тоже закон.
   Новых пакетов не добавляешь. Строки — только в ARB, цвета — только из темы.
2. Прочитай `docs/pipeline/tasks.md`, найди свою задачу: файлы, что делаем, тесты, генерация.
   Есть поле `Дизайн` — прочитай этот файл макета и раздел «Дизайн» в `brief.md` (режим),
   и изменения относительно макета в `decisions.md` — они важнее макета.
   Старый код вне задачи под `architecture.md` не переделываешь.
3. Сделай ровно её, **по TDD**: тест из поля `Тесты` → запусти, убедись, что он красный
   по ожидаемой причине → минимальный код → зелёный → рефакторинг. По каждому случаю.
   Тесты — на основные случаи из задачи, без фанатизма.
4. **Проверь фактически** — `flutter test` по тестам задачи и `flutter analyze`, покажи вывод.
   «Выглядит правильно» не считается проверкой.

## Границы

- **Только файлы, перечисленные в задаче.** Нужен другой файл — это сигнал, что задача
  описана неверно: останови работу и скажи об этом, не расширяй скоуп молча.
- **Не рефачь соседний код** «раз уж я здесь». Заметил проблему — упомяни в отчёте.
- **Не меняй контракты.** Контракт не сходится с задачей — стоп и доклад.
- Не импортируй ничего из `docs/pipeline/spikes/` — это код на выброс.
- **Не запускай генерацию файлов** (`build_runner`, `gen-l10n` и т.п.) и не правь
  сгенерированные файлы руками. Нужна генерация — стоп, верни команду для пользователя.
- Секреты не пишешь никуда: ни в код, ни в тесты, ни в вывод.
- Не отмечай задачу `[x]` в `tasks.md` сам, это сделает главный агент.

## Что вернуть

- Что сделано, по файлам.
- **Тесты и анализатор: зелёные / нет** + вывод команд.
- Нужна генерация — команда для пользователя и что должно появиться.
- Что осталось незакрытым или всплыло по пути (если всплыло).

Коротко. Не пересказывай написанный код — его и так видно в диффе.
