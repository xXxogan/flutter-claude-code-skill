# Чек-лист сайта перед запуском

Читай нужные секции. У каждого пункта: **приоритет**, **кто может закрыть**
(`авто` — ты сам / `🙋` — нужны данные или действие человека), **проверка** — чем именно
подтверждается, **ловушка** — как этот пункт обычно ломают.

Секции: `forms` (A) · `index` (B) · `meta` (C) · `trust` (D) · `a11y` (E) · `perf` (F)
· `legal` (G) · `ops` (H)

---

## A. Работает ли оно вообще — `forms`

Самая частая катастрофа запуска не в SEO. Сайт открылся, заявки уходят в никуда,
и это замечают через месяц по нулю лидов.

**WEB-01 · Форма реально доставляет заявку** — P1 · 🙋
Проверка: найди обработчик (`grep -rn "action=\|onSubmit\|fetch(" ` по формам). Убедись,
что есть серверный эндпоинт или сервис (Formspree/Resend/SMTP/CRM) и что креды заданы
в проде, а не только в `.env.example`. Финальное подтверждение — только живая тестовая
заявка, полученная человеком.
Ловушка: код формы есть, ключ сервиса не проброшен в прод-окружение → фронт показывает
«спасибо», письмо не уходит. Проверяется только отправкой.

**WEB-02 · Письма не падают в спам** — P1 · 🙋
Проверка: у отправляющего домена настроены SPF, DKIM, DMARC (`dig TXT`). Тестовое письмо
дошло во «Входящие», а не в «Спам».
Ловушка: отправка с `noreply@своийдомен` через чужой SMTP без DKIM — почти гарантированный
спам-фильтр.

**WEB-03 · Понятные состояния формы** — P2 · авто
Проверка: есть состояние отправки (спиннер/блокировка кнопки), явный успех (thank you
или inline-сообщение), понятная ошибка при сбое сети, повторная отправка не создаёт дубль.
Ловушка: двойной клик → две заявки; ошибка сети → тишина, человек уходит.

**WEB-04 · Thank you page или экран благодарности** — P2 · авто
Проверка: после отправки — отдельный URL или явный экран, к которому можно привязать цель
в аналитике.
Ловушка: alert() вместо страницы — цель в аналитике привязать не к чему.

**WEB-05 · Защита формы от спама** — P2 · авто
Проверка: honeypot-поле или Turnstile/hCaptcha invisible + серверная проверка.
Ловушка: классическая CAPTCHA с картинками режет конверсию и доступность. Ставь невидимую.

**WEB-06 · Нет битых ссылок и картинок** — P2 · авто
Проверка: собери все `href`/`src` и проверь коды ответов. Отдельно — ссылки на
несуществующие якоря и на страницы, которые «будут потом».
Ловушка: ссылки на локальные пути (`file://`, `localhost`, `/Users/...`) и на стейдж-домен.

**WEB-07 · Контакты кликабельны** — P2 · авто
Проверка: телефон — `tel:` без пробелов и скобок в значении, почта — `mailto:`,
мессенджеры — рабочие deep-ссылки. На мобиле нажатие открывает звонилку.
Ловушка: телефон картинкой или текстом — на мобиле по нему не позвонить.

**WEB-08 · CTA ведёт куда обещает и виден выше сгиба** — P1 · авто
Проверка: на первом экране мобильной ширины (375px) видно основное действие. Клик по
каждому CTA ведёт на заявленную цель.
Ловушка: «выше сгиба» проверяют на десктопе. Проверяй на мобиле — там сгиб выше.

**WEB-09 · Sticky mobile CTA не мешает** — P2 · авто
Проверка: липкая кнопка не перекрывает контент и футер (есть нижний отступ у body),
учтён `env(safe-area-inset-bottom)` для iPhone, кнопка не всплывает поверх открытой формы.
Ловушка: sticky-панель закрывает поле ввода на маленьких экранах.

**WEB-10 · Кастомная 404 и правильный статус** — P2 · авто
Проверка: `curl -sI <url>/zzz-not-exists` → первая строка содержит `404`. Страница
осмысленная: ссылка на главную, поиск, контакты.
Ловушка: **soft 404** — SPA и часть CMS отдают `200 OK` с текстом «не найдено».
Google индексирует такие страницы как обычные. Это самая частая ошибка пункта.

**WEB-11 · Поведение при сбое** — P3 · авто
Проверка: страница 500 не показывает stack trace; если контент грузится из API —
есть состояние ошибки и загрузки, а не бесконечный скелетон.

## B. Индексация — `index`

Одна строка здесь стоит дороже всего остального чек-листа вместе взятого.

**WEB-12 · robots.txt существует и не блокирует прод** — P1 · авто
Проверка: `curl -s <url>/robots.txt`. Убедись, что нет `Disallow: /` для `User-agent: *`.
Есть строка `Sitemap:` с абсолютным URL.
Ловушка №1: стейдж-версия `robots.txt` уехала в прод и закрыла весь сайт.
Ловушка №2: robots.txt ничего не защищает — закрытая в нём страница всё равно доступна
всем и может попасть в индекс по внешним ссылкам. Приватное закрывается авторизацией.

**WEB-13 · Снята пред-релизная блокировка** — P1 · авто
Проверка: в HTML нет `<meta name="robots" content="noindex">`, в ответе нет заголовка
`X-Robots-Tag: noindex`, снят basic auth, у WordPress снята галка «Попросить поисковые
системы не индексировать».
Ловушка: `noindex` ставят на время разработки и забывают. Сайт живёт, трафика нет.

**WEB-14 · sitemap.xml актуален** — P2 · авто
Проверка: доступен, отдаёт `200`, содержит только каноничные URL прода, без 404 и редиректов
внутри, без стейдж-домена.

**WEB-15 · Canonical на каждой странице** — P2 · авто
Проверка: `<link rel="canonical">` с абсолютным URL, указывает сам на себя, домен —
прод, схема — https.
Ловушка: canonical со всех страниц на главную — классическая ошибка шаблона, выкидывает
из индекса всё, кроме главной.

**WEB-16 · Один хост, одна схема, один вид URL** — P1 · авто
Проверка: `curl -sIL` для четырёх вариантов — `http://`, `https://`, `www.`, без `www.`,
плюс со слешем на конце и без. Все должны сойтись **одним** 301 на один канонический вид.
Ловушка: цепочки редиректов (`http → http://www → https://www`) и, хуже, петля.

**WEB-17 · Редиректы со старых URL** — P1 при редизайне · 🙋
Проверка: если сайт заменяет существующий — список старых URL (из Search Console/логов)
и 301 на новые адреса. Не все на главную — на смысловые соответствия.
Ловушка: массовый 301 на главную Google трактует как soft 404; накопленные позиции теряются.

**WEB-18 · Search Console и Вебмастер** — P2 · 🙋
Проверка: владение подтверждено, sitemap отправлен, ошибки покрытия просмотрены.
Аналитика не индексирует — это разные инструменты, GA сюда не считается.

**WEB-19 · Язык и локали** — P3 · авто
Проверка: `<html lang="ru">`. Если версий несколько — взаимные `hreflang` + `x-default`.

## C. Мета, превью, навигация — `meta`

**WEB-20 · Уникальные title** — P2 · авто
Проверка: собери title всех страниц, проверь на дубли. Ориентир ~60 символов, смысл —
в начале, бренд — в конце.
Ловушка: у сайта на React title один на всё приложение, если его не выставляют роутером.
На уже проиндексированном сайте массово не переписывай — это отдельное решение с оценкой риска.

**WEB-21 · Уникальные description** — P3 · авто
Проверка: есть, уникальны, ~150–160 символов, читаются как обещание, а не как список
ключевых слов.

**WEB-22 · OG и Twitter-превью** — P2 · авто
Проверка: `og:title`, `og:description`, `og:url`, `og:type`, `og:image` (1200×630, **абсолютный**
URL, < 5 МБ), `twitter:card=summary_large_image`. Проверь реальную отдачу картинки: `curl -sI`.
Ловушка: относительный путь в `og:image` — соцсети его не резолвят, превью пустое.

**WEB-23 · Иконки и манифест** — P3 · авто
Проверка: `favicon.ico`, `apple-touch-icon` 180×180, `site.webmanifest`, `theme-color`.

**WEB-24 · Хлебные крошки** — P3 · авто
Проверка: ставятся только если иерархия реально есть. Разметка `BreadcrumbList` **совпадает**
с видимыми на странице крошками.
Ловушка: разметка есть, крошек на странице нет → расхождение разметки и контента.

**WEB-25 · Внутренняя перелинковка** — P3 · авто
Проверка: с каждой страницы есть ≥1 осмысленная ссылка вглубь сайта; нет страниц-сирот,
на которые не ведёт ни одна ссылка из меню или текста.
Ловушка: «Подробнее» ×20 — ссылки без смысла в анкоре.

## D. Контент и доверие — `trust`

**Вся эта секция — про реальные данные бизнеса. Здесь ты почти всегда 🙋.**
Генерация чего-либо из этого списка — не помощь, а фальсификация.

**WEB-26 · Реальные отзывы** — P2 · 🙋
Проверка: отзывы существуют вне сайта (Яндекс.Карты, Google, 2ГИС, маркетплейс, соцсети),
есть имя и, по возможности, ссылка на источник.
Ловушка: сгенерированные отзывы — прямое нарушение (ФАС/ЗоЗПП в РФ, отдельное правило FTC
в США со штрафами за отзыв). Разметку `Review`/`AggregateRating` ставь **только** на реально
собранные отзывы, иначе это structured data spam и ручные санкции Google.

**WEB-27 · Кейсы** — P3 · 🙋
Проверка: цифры и результаты подтверждены клиентом. Логотипы заказчиков — только с разрешения.

**WEB-28 · FAQ из настоящих вопросов** — P3 · 🙋
Проверка: 5 вопросов, которые реально задают (спроси у владельца — что спрашивают по телефону).
Разметка `FAQPage` только если ответы видны на странице.
Ловушка: придуманные вопросы вида «Почему вы лучшие?» — не FAQ, а самореклама, и в выдаче
не работают.

**WEB-29 · Обещание времени ответа** — P2 · 🙋
Проверка: бизнес реально держит заявленный срок. «Ответим за 15 минут» — публичное обещание.
Ловушка: обещание в ночь и в выходные без дежурного — минус доверие вместо плюса.

**WEB-30 · Фото команды и объектов** — P3 · 🙋
Проверка: настоящие фото, права на них есть.
Ловушка: сток вместо команды узнаётся мгновенно и работает против доверия.

**WEB-31 · Адрес, карта, маршрут, часы** — P2 · 🙋
Проверка: адрес и телефон **совпадают** с карточкой в Яндекс.Бизнес / Google Business
Profile / 2ГИС до символа (единый NAP). Карта грузится, маршрут строится.
Ловушка: карта на iframe без lazy-загрузки утяжеляет страницу на мегабайты.

**WEB-32 · Локальная разметка** — P3 · 🙋
Проверка: `Organization` или `LocalBusiness` (только для бизнеса с реальным адресом и приёмом
посетителей), поля совпадают с видимым текстом. Валидируй в Rich Results Test.
Ловушка: разметка с выдуманным адресом/рейтингом = spam-политика Google → ручные санкции.

## E. Доступность — `a11y`

**WEB-33 · Правильный alt** — P2 · авто
Проверка: содержательным картинкам — описание сути (не имя файла). **Декоративным —
пустой `alt=""`**, не описание.
Ловушка: автогенерация alt для всех подряд создаёт шум для скринридера и не даёт SEO-эффекта.
Текст на картинке (цены, условия) обязан дублироваться текстом на странице.

**WEB-34 · Контраст и размер текста** — P2 · авто
Проверка: контраст текста к фону ≥ 4.5:1 (крупный — 3:1). Базовый шрифт на мобиле ≥ 16px.
Ловушка: светло-серый текст на белом в футере и подписях к формам.

**WEB-35 · Клавиатура** — P3 · авто
Проверка: Tab проходит по странице в логичном порядке, фокус **видим** (не `outline: none`
без замены), из модалки можно выйти по Esc, фокус не улетает под sticky-панель.

**WEB-36 · Семантика и формы** — P2 · авто
Проверка: один `h1`, заголовки без перепрыгивания уровней, `header/nav/main/footer`,
у каждого поля формы — `label` (не только placeholder), ошибки связаны с полем.
Ловушка: placeholder вместо label — при вводе подсказка исчезает.

**WEB-37 · Тач-таргеты** — P3 · авто
Проверка: кликабельные элементы ≥ 44×44px, соседние ссылки не слипаются.

## F. Скорость — `perf`

**WEB-38 · Изображения по размеру и формату** — P2 · авто
Проверка: нет картинок 3000px в слоте 400px; формат webp/avif; вес главного экрана разумный.
Ловушка: фон-героя на 4 МБ — это весь бюджет LCP.

**WEB-39 · Нет скачков вёрстки (CLS)** — P2 · авто
Проверка: у `<img>` заданы `width`/`height` или `aspect-ratio`; у баннеров и объявлений
зарезервировано место; шрифт не двигает текст при подгрузке.

**WEB-40 · Ленивая загрузка — но не для главного** — P2 · авто
Проверка: `loading="lazy"` у картинок ниже сгиба. **LCP-картинка первого экрана — без lazy**,
лучше с `fetchpriority="high"`.
Ловушка: массовый `lazy` на всё ухудшает LCP вместо улучшения.

**WEB-41 · Шрифты** — P3 · авто
Проверка: `font-display: swap`, preload основного начертания, не больше 2–3 начертаний,
подключение с собственного домена, а не из трёх внешних источников.

**WEB-42 · Замер, а не ощущение** — P2 · авто
Проверка: PageSpeed Insights / Lighthouse **в мобильном профиле**. Ориентир: LCP < 2.5 c,
CLS < 0.1, INP < 200 мс. Запиши цифры в отчёт.
Ловушка: замер на десктопе и на быстром интернете. Пользователь сидит в 4G с телефона.

## G. Юридическое и данные — `legal`

Ты не юрист. Всё в этой секции — черновик и указание на риск, а не готовый документ.
Так и пиши в отчёте.

**WEB-43 · Политика конфиденциальности** — P1 · 🙋
Проверка: страница существует, на неё есть ссылка из футера и из-под форм, в тексте —
кто оператор (реквизиты), какие данные собираются, зачем, сколько хранятся, кому передаются
(включая аналитику), как отозвать согласие, контакт для обращений.
Ловушка: сгенерированный текст с чужими реквизитами и упоминанием GDPR «на всякий случай».
Черновик — можно; выдавать за юридический документ — нельзя. Помечай: «требует проверки юристом».

**WEB-44 · Согласие на обработку персональных данных** — P1 (РФ) · авто
Проверка: у каждой формы — чекбокс согласия, **не предустановленный**, со ссылкой на политику;
факт согласия сохраняется вместе с заявкой.
Ловушка: «Нажимая кнопку, вы соглашаетесь» мелким шрифтом — слабая позиция; чекбокс надёжнее.
Отдельно: 152-ФЗ требует уведомления Роскомнадзора об обработке ПД — это к владельцу бизнеса.

**WEB-45 · Cookie-баннер и порядок загрузки счётчиков** — P2 · авто
Проверка: если стоит аналитика/пиксели — баннер есть, и **скрипты не грузятся до согласия**.
Для трафика из ЕС — Google Consent Mode v2.
Ловушка: баннер стоит «для вида», а GA грузится в `<head>` до любого клика — это ровно то
нарушение, от которого баннер должен был защитить.

**WEB-46 · Реквизиты продавца** — P1 (РФ) · 🙋
Проверка: наименование ИП/ООО, ИНН, юр. адрес, контакты — в футере или на отдельной странице.
Для интернет-магазина обязательны также условия оплаты, доставки, возврата и оферта.

**WEB-47 · Права на контент** — P3 · 🙋
Проверка: фотографии, иконки, шрифты, тексты — свои или лицензированы. Коммерческая лицензия
у шрифта проверяется отдельно от бесплатности скачивания.

## H. Аналитика, инфраструктура, сопровождение — `ops`

**WEB-48 · Аналитика стоит один раз и работает** — P2 · 🙋
Проверка: счётчик установлен один раз (нет дублей из шаблона и из GTM), ID — **свой**,
в проде фиксируются заходы (посмотри реалтайм).
Ловушка: скопированный из примера чужой measurement ID; счётчик только на главной.
Альтернатива без cookie-баннера: Plausible/Umami — уместно предложить, если аналитика нужна
ради базовых цифр.

**WEB-49 · Цели настроены** — P2 · авто
Проверка: события на отправку формы, клик по телефону, клик в мессенджер. Без целей запуск
нечем измерять.

**WEB-50 · HTTPS и сертификат** — P1 · авто
Проверка: `curl -sI` — валидный сертификат, автопродление включено, весь http редиректится
на https, в HTML нет ресурсов по `http://` (mixed content).

**WEB-51 · Домен и доступы** — P1 · 🙋
Проверка: домен зарегистрирован **на владельца бизнеса**, а не на подрядчика; дата истечения
известна, автопродление включено; у владельца есть доступы к хостингу, домену, почте, аналитике.
Ловушка: домен на аккаунте разработчика — самый дорогой сюрприз через год.

**WEB-52 · Бэкап и мониторинг** — P2 · 🙋
Проверка: есть резервная копия сайта и БД + понятный способ восстановления; настроен
uptime-мониторинг с уведомлением.
Ловушка: бэкап есть, восстановление никогда не пробовали.
