# Шаблоны артефактов

Копируй структуру, но не тащи пустые разделы: нечего написать в раздел — удали его,
а не оставляй «TBD». Исключение — `state.md`, он всегда полный.

---

## state.md

```markdown
# Состояние пайплайна

Проект: <имя>
Обновлено: <YYYY-MM-DD>

Фаза: **1 — UI**
Текущая стадия: **7 — implementation**
Ворота: пройдены до стадии 6 включительно (пользователь подтвердил 2026-07-22)

Следующее действие: T-05 «Отметка привычки за сегодня»

## История стадий
Фаза 1:
- 0 context load — 2026-07-22
- 1 idea — 2026-07-22
- 2 plan + criteria — 2026-07-22
- 3 risk spikes — 2026-07-22 (спайк 02 изменил план: см. decisions.md)
- ...
```

## brief.md

```markdown
# Project Brief: <имя>

## Суть
3–5 предложений: что строим, для кого, какую боль снимаем, что считается успехом.

## Пользователь и сценарий
Кто пользуется, как часто, в какой ситуации открывает приложение.

## Скоуп
**В скоупе:** ...
**Вне скоупа (non-goals):** ...

## Дизайн
Макет: <путь> | нет. Режим: строго | ориентир (по умолчанию строго).
Что берём из макета: ... Что не берём: ...
Изменения относительно макета — в `decisions.md`, они важнее макета.

## Тема и шрифты
Seed-цвет и акценты (или «из макета»), шрифт, светлая/тёмная.

## Базовая точка (только для проекта, где код уже есть)
`flutter analyze`: N замечаний на <дата>. Красные тесты: ... Требование — ноль новых.

## Отступления от архитектуры
Платформы — iOS, Android, Web; архитектура и пакеты — по `architecture.md` скилла.
Здесь — только отступления от него (со ссылкой на `decisions.md`) и пакеты сверх
обязательного набора. В проекте, где код уже есть, — как устроен старый код там,
где он расходится с `architecture.md`. Старый код под архитектуру не переделывается
без просьбы пользователя.

## Внешние зависимости
Источник данных / API: адрес, авторизация, лицензия, ToS-ограничения, лимиты.
Секреты — только именами, никогда значениями.

## Ограничения и риски
Список. Каждый риск — с указанием, чем он закрыт: спайком, дизайном, или «принят как есть».

## Локализация
Языки, основной язык.

## Как запускать
Установка зависимостей, что генерируется и какой командой (запускает пользователь),
команда запуска, команда тестов, анализатор.
Заполняется на стадии 5 теми командами, которые реально отработали, и уточняется на 9.
Пустой раздел блокирует аудит: аудитору нечем проверять.

## Глоссарий
Термины предметной области, если они не самоочевидны.
```

## contracts.md

```markdown
# Контракты

## Фаза 1 — UI

### Фичи и маршруты
| Фича | Страницы | Маршрут | Экспорт из barrel |
|---|---|---|---|
| habits | HabitsPage | `home/habits` | HabitsPage |

### Брейкпоинты и раскладки
| Ширина | Раскладка | Навигация |
|---|---|---|
| < <N> | ... | ... |

### Модели данных
```dart
// features/habits/data/models/habit_model.dart
class HabitModel {
  const HabitModel({required this.id, required this.title, required this.streakDays,
      this.lastDoneOn});

  final String id;            // UUID v4
  final String title;
  final int streakDays;       // >= 0
  final DateTime? lastDoneOn; // локальная дата без времени; null = ни разу
}
```

### Репозитории
Интерфейс фиксируется здесь и в фазе 2 не меняется.
```dart
// features/habits/data/repositories/habit_repository.dart
abstract class HabitRepository {
  /// Ошибки: [HabitsNetworkError], [HabitNotFoundError].
  Future<List<HabitModel>> getAll();
  Future<HabitModel> markDone(String habitId, DateTime day);
}
```
Фейковая реализация (`FakeHabitRepository`): 5 привычек, одна с серией 0, задержка 500 мс,
чтобы был виден shimmer.

### Состояния Cubit
```dart
// features/habits/presentation/cubit/habits_state.dart
@freezed
sealed class HabitsState with _$HabitsState {
  const factory HabitsState.loading() = HabitsLoading;
  const factory HabitsState.loaded(List<HabitModel> habits) = HabitsLoaded;
  const factory HabitsState.empty() = HabitsEmpty;
  const factory HabitsState.error(HabitsError error) = HabitsFailure;
}
```
| Состояние | Что видит пользователь |
|---|---|
| loading | shimmer-скелетон списка |
| empty | подсказка «Добавьте первую привычку» |
| error | текст ошибки и кнопка «Повторить» |

Методы Cubit: `load()`, `markDone(String habitId)`.

### Ключи локализации
| Ключ | Экран | Текст (основной язык) |
|---|---|---|
| `habitsEmptyHint` | HabitsPage | Добавьте первую привычку |

## Фаза 2 — бэкенд

### Модели: JSON
К моделям фазы 1 добавляется `@JsonSerializable()` и `@JsonKey(name: ...)` по реальному API.

### API
```dart
// features/habits/data/api/habits_api.dart
@RestApi()
abstract class HabitsApi {
  @GET('/habits')
  Future<List<HabitModel>> getAll();

  @POST('/habits/{id}/done')
  Future<HabitModel> markDone(@Path('id') String id, @Field('day') String day);
}
```

### Схемы ответов источника
Что реально приходит и какие поля мы берём. С примером.

### Хранилище
Hive-боксы: что в каждом, ключ идентичности записи и почему именно он.

### Конфигурация (`core/config/app_config.dart`)
| Константа | Тип | Значение | Смысл |
|---|---|---|---|
| `apiBaseUrl` | `String` | `https://api.example.com` | базовый адрес API |

### Секреты и доступы
| Имя | Что это | Где получить | Где живёт |
|---|---|---|---|
| `SYNC_API_KEY` | ключ к API синхронизации | кабинет сервиса | только на сервере, в приложение не попадает |

Значения здесь не пишутся никогда — ни здесь, ни в коде, ни в git, ни в сборке.

### Ошибки
| Ошибка фичи | Из чего делается | Что делает Cubit | Что видит пользователь |
|---|---|---|---|
| `HabitsNetworkError` | `DioException` таймаут / нет сети | `error` | «Нет соединения» + «Повторить» |
```

## Стоит починить
- ...

- `файл:строка` — какое правило `architecture.md` нарушено.

## Наблюдения
- ...

## Acceptance criteria — сводка
| AC | Статус | Как проверено |
|---|---|---|
